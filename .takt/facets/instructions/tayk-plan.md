Report Directory の **実装ブリーフ（`intake-brief.md`）** を読み、要件 ID を採番したうえで実装方針を立ててください。**この step ではコードを書きません。**

## 手順

1. **ブリーフの読み込み**: Report Directory の `intake-brief.md` を Read で開き、「確定している決定」「要件候補」「対象外」「制約」を読む。ブリーフに書かれていない要求を足さない
2. **要件 ID の採番**: 要件候補に `REQ-<issue番号>-<2桁連番>` を振る。Policy の採番規則に従う。ここで振った ID は後段で不変
3. **ADR の確認**: Knowledge の Source Path を Read で開き、ADR 本文を取得する。今回の変更が ADR-0001 の 7 決定のどれに触れるかを特定する
4. **現状の把握**: 対象ファイルを Read / Glob / Grep で確認する。tayk はまだ実装が薄いため、**「既存にならう」が成立しない前提**で、新規に置く構造を明示的に決める
5. **実装方針**: 要件 ID ごとに、変更する / 新規作成するファイルと、そこで行うことを書く
6. **ADR 逸脱の事前申告**: 方針が ADR の決定から外れるなら、外れる点・技術的正当性・ADR 改訂案をここで申告する。**黙って逸脱しない**（ADR-0001 の決定 7）
7. **リスクの洗い出し**: 実装中に判断が割れそうな点を挙げ、どう決めるかを先に書く

## 制約

- **1 MCP tool = 実装 1 ファイル + テスト 1 ファイル**。schema / service / index への分割を方針に含めない
- **registry を置かない**。tool 一覧は entry point のフラットな import 配列のみ
- **エラーは内部 throw、境界で変換**。`Result` 型 / `createService` フレームを導入しない
- tayk が読み書きするファイルはすべて JSON（YAML 禁止）
- v0.1.0 のゲート（collection フルライフサイクル 1 周の dogfood 完走）に不要な拡張を方針へ入れない。必要性を感じたら issue 化を提案する
- パッケージ操作は ni / nr / nlx 経由で記述する（`npm install` と書かない）

## 判定

- 要件 ID がすべて実装方針に対応づいた → 次へ
- ブリーフの決定だけでは方針が一意に決まらない → ABORT し、何が決まれば進めるかを列挙する
