レビュー指摘を修正してください。

対応対象:
- PR: `#{structured:review_triage.pr_number}`
- 状況: {structured:review_triage.summary}
- 指摘: {structured:review_triage.actionable}

**これは {step_iteration} 回目のレビュー指摘修正です。**

## 手順

1. `actionable` の指摘を severity 順（`blocking` → `should` → `nit`）に処理する
2. 指摘ごとに、**指摘された箇所そのもの**を直す。周辺の「ついで直し」をしない（レビューの差分追跡が壊れる）
3. 同種の問題が指摘箇所以外にもあるなら、その箇所も直す。ただし修正内容として明示的に報告する
4. 修正後、影響範囲のテストをローカルで実行する（`nr test`）
5. commit・push する:
   - 日本語 Conventional Commits + タイトル末尾に `(#<N>)`
   - 指摘の出所が分かる本文にする（例: 本文に `CodeRabbit の指摘: <要約>`）

## 制約

- 指摘の解消を装わない。表面だけ変えて実質が変わっていない修正は、次のトリアージで再検出される
- ADR に反する修正を、レビュー指摘を理由に行わない。指摘と ADR が衝突するときは **ADR が優先**。その場合は修正せず、衝突の事実を報告する
- テストの削除・skip・アサーションの緩和で指摘を消さない
- 実装計画の要件 ID から外れる機能追加を、レビュー指摘を理由に行わない（スコープ超過）

## 判定

- 全 actionable を修正して push した → CI 確認へ戻る
- 指摘が実装方針そのものの誤りを突いており、この step では直せない → 差し戻す
- 指摘と ADR が衝突する → 修正せず、衝突を報告して差し戻す
