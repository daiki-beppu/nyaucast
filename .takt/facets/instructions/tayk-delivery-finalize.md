PR を人間のレビュー待ち状態として着地させ、受け渡しの記録を残してください。

## 手順

1. PR の最終状態を確認する: `gh pr view --json number,url,state,mergeable,reviewDecision,statusCheckRollup`
2. PR 本文を最新化する。以下を必ず含める:
   - `Closes #<N>`（linked issue）
   - 要件 ID ごとの充足状況（実装計画の要件一覧と、対応する差分の場所）
   - テスト実行結果（実際のコマンドと結果）
   - ADR 整合性の結論
   - 対応しなかったレビュー指摘とその理由
3. トリアージで `dismissed` に分類した指摘があれば、**その理由を PR にコメントで残す**:
   `gh pr comment <N> --body "..."`
   指摘元に対して、なぜ対応しないのかが伝わる文面にする
4. 未解決のまま残るもの（後続 issue 化した項目、flaky として扱った CI 失敗）があれば列挙する

## 制約

- **PR をマージしない。** マージは人間の判断
- CI が緑でないまま「完了」と報告しない。緑でないなら、その事実と理由を明記する
- 実態と異なる充足状況を書かない。未実装の要件は未実装と書く
- 後続 issue を勝手に作らない（必要性は報告に留め、起票は人間の判断に委ねる）

## 判定

- PR が最新化され、記録が残った → 完了
