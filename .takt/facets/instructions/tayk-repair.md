承認された診断（`diagnosis.md`）の修正方針に従って、**原因を除いて**ください。症状を止めるのではなく、因果の連鎖を断ちます。

## 手順

1. 診断レポートの「因果の連鎖」と「修正方針」を読み、**どこを断つか**を確認する
2. 要件 ID ごとに修正する。診断で採番された ID から外れる変更をしない
3. 修正後、まず**再現テストを実行する**:
   ```
   nr test
   ```
   - 再現テストが red → green に変わったこと（症状が消えたこと）
   - 既存挙動の回帰テストが green のままであること（何も壊していないこと）
4. 影響範囲で洗い出した呼び出し元を Read で開き、修正が既存契約を壊していないかを目で確認する。テストの緑だけを根拠にしない
5. 変更した全ファイルの差分を「必須変更 / 関連変更 / 不要変更」に分類する。**不要変更が 1 つでも残っていれば完了しない**（Policy の既存システム尊重ポリシー）

## 制約

- **診断で断つと決めた箇所以外を直さない。** 修正ファイル内という理由だけの整理・改名・リファクタを混ぜない
- 再現テストを green にするために、テストの期待値を緩めない・skip しない・削除しない
- ADR に反する修正をしない。修正方針が ADR と衝突すると分かったら、修正せず報告して差し戻す
- 診断で申告した ADR 逸脱がある場合、**該当 ADR の改訂を同じ差分に含める**（ADR-0001 決定 7 / ADR-0008 決定 4）
- 修正中に見つけた「今回の修正と因果のない問題」は、その場で直さず「スコープ外の発見」節に記録する（Policy のスコープ外発見ポリシー）
- パッケージ操作・スクリプト実行は ni / nr / nlx 経由

## 対症療法の自己検査

修正を書き終えたら、次を自分に問うこと。1 つでも「はい」なら対症療法である。

- 原因の箇所はそのままで、症状が出る**手前**に検査・early return・try-catch を足しただけではないか
- 「値が想定外なら弾く」を足したが、**なぜ想定外の値が来るのか**は変わっていないのではないか
- 再現テストは green になったが、診断の「因果の連鎖」のどの段も変わっていないのではないか

対症療法だと判断したときは、修正を捨てて診断へ差し戻すこと。**通ったテストを理由に対症療法を残さない。**

## 判定

- 原因を除き、再現テストが green、既存挙動の回帰が green → 実装レビューへ
- 修正が対症療法にしかならない（原因を除くには診断の範囲を超える変更が要る）→ 診断へ差し戻す
- 修正方針が ADR と衝突する → 修正せず、衝突を報告して診断へ差し戻す
- 修正しても再現テストが red のまま → 診断へ差し戻す。原因の特定が誤っているか、原因が複数ある
