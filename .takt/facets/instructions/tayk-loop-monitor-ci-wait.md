CI の完了待ち（ci_wait → ci_check）が {cycle_count} 回繰り返されました。まだ結果が確定していません。

CI が正常に進行しているのか、詰まっているのかを判断してください。

**確認すること:**

1. `gh pr checks --json name,state,bucket,startedAt,completedAt` で、各チェックの開始時刻と現在の状態を確認する
2. `gh run list --limit 5 --json status,conclusion,createdAt,updatedAt` で、実行がキューで滞留していないかを確認する

**判断基準:**

- **進行中**: チェックが実際に走っており、`startedAt` が更新されている、または典型的な実行時間の範囲内である
- **詰まっている**:
  - キュー待ちのまま長時間動いていない（runner の枯渇・権限待ち）
  - 承認待ち（`waiting` / environment approval）で人間の操作を待っている
  - チェックの取得自体が失敗し続けている（権限不足・API エラー）
  - push した commit に対して CI が起動していない（ワークフローのトリガ条件に合致していない）

**判断:**

- 進行中なら待機を継続してください。CI の実行時間はリポジトリによって大きく異なり、待つこと自体は失敗ではありません
- 詰まっているなら打ち切ってください。人間の操作を待つ状態は、待ち続けても解消しません

打ち切るときは、**何が原因で止まっているか**（承認待ち / runner 枯渇 / トリガ条件の不一致 / 権限）と、**人間が何をすれば進むか** を報告に明記してください。
