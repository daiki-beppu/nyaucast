review_wait → review_triage のループが {cycle_count} 回繰り返されました。トリアージが `awaiting`（レビューの結論がまだ出ていない）を返し続けている状態です。

**この時点で `review_fix` は一度も走っていない可能性があります。** 修正の質を問う段階ではなく、**そもそもレビューが返ってくるのか**を判断してください。

**確認すること:**

1. `gh pr view --json reviews,comments,statusCheckRollup` で、自動レビュアーが実際に起動した形跡があるかを見る
2. `gh pr checks` で、レビュー系の check が queued / in_progress のまま滞留していないかを見る
3. 直近の push からの経過時間が、そのレビュアーの通常の応答時間を超えているか

**判断基準:**

- 自動レビュアーが起動しており進行中か
  - 進行中 → 健全。レビュー完了まで数分かかるのは正常であり、待機を継続してよい
  - 起動した形跡がない → 待ち続けても結論は出ない。bot 未設定・権限不足・トリガ条件の不一致を疑う
- コメントは投稿されているのに `awaiting` が返り続けていないか
  - 返り続けている場合、レビュアー側ではなく**トリアージ側が結論を読み取れていない**。この場合も待機は無意味である
- 投稿済みの指摘が `nit` だけで、`blocking` / `should` が出ていないか
  - その状態が続くなら実質的に収束している。完了へ進めてよい

**待機の継続を選べるのは、レビューが動いている根拠を示せるときだけです。** 「まだ来ていないのでもう一度待つ」は根拠になりません。動いていない待機を続けることは、無人実行では単なるコストです。

打ち切りまたは前進を選ぶときは、**レビュアーが起動しなかったのか / 起動したが結論が読めなかったのか**を報告に書き分けてください。前者は PR 設定の問題、後者はトリアージ設計の問題であり、人間が次に直す場所が変わります。
