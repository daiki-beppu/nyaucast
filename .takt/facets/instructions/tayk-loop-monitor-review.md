レビュー指摘の解消ループ（ci_wait → ci_check → review_wait → review_triage → review_fix）が {cycle_count} 回繰り返されました。**修正（review_fix）を挟んで一周しても指摘が尽きていない状態です。**

PR のレビュー状況を確認し、指摘の解消が収束しているかを判断してください。

**確認すること:**

1. `gh pr view --json reviews,comments,reviewDecision` で、指摘の総数と解決状況の推移を見る
2. Report Directory 内の delivery レポートで、前サイクルまでに何を修正したかを確認する

**判断基準:**

- 未解決の指摘件数が減っているか
  - 減っている → 健全。自動レビューは修正のたびに新しい指摘を出すため、数サイクル回ること自体は正常
  - 減っていない、または増えている → 非生産的
- 同じ箇所への指摘が繰り返されていないか
  - 繰り返している → 修正が指摘の意図に届いていない
- 修正が新しい指摘を生む連鎖になっていないか
  - 修正 → 別の指摘 → 修正 → また別の指摘、が続く場合、実装方針そのものがレビュアーの想定と食い違っている。**実装の修正へ差し戻す**
- 指摘と ADR が衝突していないか
  - 衝突している場合、workflow 内では決着しない。**打ち切る**（ADR 改訂の是非は人間の判断）
- `nit` だけが残っていないか
  - `blocking` / `should` が解消され `nit` だけが残っている状態が続くなら、実質的に収束している。完了へ進めてよい

**打ち切り（ADR 衝突・方針の食い違い）を選ぶときは、何が争点になっているかを報告に明記してください。** レビュアーの指摘と実装方針のどちらが正しいかは人間が決めることであり、その判断材料を残すのがこの監視の役割です。
