設計レビューの指摘を、**計画とテスト設計のレポートを直して** 解消してください。**プロダクションコードは書きません。**

## 手順

1. Report Directory の設計レビューレポート 3 種（設計 / ADR 整合性 / テスト設計）をすべて読む
2. `new` / `persists` / `reopened` の全 finding を列挙する。**取捨選択しない**
3. finding ごとに対応方針を決める:
   - **修正する**: 計画レポート / テスト設計レポートを書き換える
   - **修正しない**: 指摘が事実誤認である根拠を、レポートの該当箇所を引用して示す
4. 実装計画（`plan.md`）とテスト設計（`test-design.md`）のファイルを直接書き換える
5. 要件 ID は **振り直さない**。要件が分割されたときは枝番（`REQ-55-03a` / `REQ-55-03b`）を足す
6. ADR 整合性レビューが NEEDS_ADR_REVISION を出しているなら、計画の「ADR 整合性の事前申告」に逸脱点・技術的正当性・ADR 改訂案を追記する（ADR 本文の改訂は実装 step で行う）

## 制約

- **プロダクションコード・テストコードを書かない。** この step で触るのはレポートファイルのみ
- finding を黙って落とさない。修正しないなら理由を書く
- 指摘の解消を装わない。レポートの文言だけ変えて実質が変わっていない修正は、次のレビューで `reopened` になる
- 指摘されていない箇所を、ついでに書き換えない（レビューの差分追跡が壊れる）

## 判定

- 全 finding に対応（修正 or 反論）した → 設計レビューへ戻る
- 指摘が計画の前提そのものを否定しており、レポート修正では解消できない → 再計画へ差し戻す
