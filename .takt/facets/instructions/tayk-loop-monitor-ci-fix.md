ci_check → ci_fix → ci_wait のループが {cycle_count} 回繰り返されました。CI の失敗を直しては再び失敗しています。

Report Directory 内の delivery レポートと、直近の CI 失敗内容を確認し、修正が収束しているかを判断してください。

**判断基準:**

- 失敗しているチェックと原因が毎回同じか
  - 同じ → 非生産的。修正が原因に届いていない
  - 異なる（直すたびに別の失敗が出る）→ 実装かテスト設計に構造的な誤りがある。**実装の修正へ差し戻す**
- 失敗の原因が **テスト設計の誤り**（期待値そのものが誤っている）に帰着していないか
  - 帰着している場合、CI 修正では解けない。**実装の修正へ差し戻す**
- 失敗が flaky（同一コミットで結果が揺れる）と判断されていないか
  - flaky なら、その旨を記録したうえで進める判断もありうる。ただし「flaky ということにして通す」のは禁止。同一コミットで緑と赤の両方が観測された記録が必要
- 環境要因（依存のインストール失敗・外部サービスの不調・rate limit）による失敗ではないか
  - 環境要因なら、コードを直しても解決しない。**打ち切る**

**打ち切り（ABORT）を選ぶ基準:**

環境要因、または CI 設定そのものの誤りが原因で、コードの修正では解決しないと判断できる場合。

**禁止:**

テストの削除・skip・アサーションの緩和・lint 無効化で CI を通す判断を、この監視から提案してはなりません。それらが唯一の解に見えるなら、実装かテスト設計が誤っているということです。
