<!--
  tayk-review の汎用レビュー出力契約。ai-antipattern / coding / testing の 3 観点が共有する。
  観点固有の検証構造を持つ 2 観点（spec-conformance の受入条件照合表、
  adr-conformance の ADR 照合表）だけが専用の契約を持ち、それ以外はこの 1 本に寄せる。

  builtin の ai-antipattern-review / coding-review / testing-review 契約を使わない理由は
  1 つだけ —— 決定 6 の 2 分類（ブロッキング / 非ブロッキング）の節を持たないため、
  tayk-review-convergence policy を効かせても指摘の書き場所が無い。
-->

```markdown
# {観点名} レビュー

## 結果: APPROVE / REJECT

## サマリー

{1-2文で結果を要約}

## レビュー範囲

| 対象        | 見た範囲                     |
| ----------- | ---------------------------- |
| `file:line` | {この観点から何を確認したか} |

## ブロッキング指摘

<!--
  ブロッキングにできるのは次のいずれか（tayk-review-convergence）:
  1. 前回までに自分が出した指摘が未解消のまま残っている（初出ラウンドと経緯を書く）
  2. 成果物を無効化する新規指摘 —— (a) 要件を満たさないものが作られる・検証されない
     (b) 誤った原因の上に修正が積まれる (c) データ破壊・誤公開・認証破壊の実害に直結する。
     いずれも具体的な反例または file:line の観測で示せること
  根拠を書けない指摘はここに載せない。
-->

| #   | 重大度              | 場所        | 問題         | 無効化の根拠 / 初出ラウンド       | 修正方針   |
| --- | ------------------- | ----------- | ------------ | --------------------------------- | ---------- |
| 1   | high / medium / low | `file:line` | {現在の欠陥} | {反例・観測 / round 1 から未解消} | {修正方針} |

## 非ブロッキング指摘

<!--
  常に非ブロッキング: 形式・体裁・記載整備、実体は要求を満たしているが文書側が
  追随していないだけの乖離、より良い書き方の提案。
  2 回目以降に見つけた新規指摘も、無効化を示せない限りここへ入る。
  破棄せずに記録すること（呼び出し側が起票の要否を判定する）。
-->

| #   | 対象        | 問題   | 修正案 | 無効化に当たらない理由 |
| --- | ----------- | ------ | ------ | ---------------------- |
| 1   | `file:line` | {内容} | {提案} | {理由}                 |

## 解消済み（前回ラウンドがある場合のみ）

| 前回の指摘 | 解消の証跡  |
| ---------- | ----------- |
| {指摘内容} | `file:line` |

## 再走査証跡（2 回目以降のレビューで必須）

<!-- 「変更なし」とだけ書かない。照合した範囲を具体的に書く。APPROVE のときも省略しない -->

| 再照合した範囲 | 根拠（`file:line` または「該当なし」） |
| -------------- | -------------------------------------- |
| {範囲}         | `file:line`                            |

## 出力整合性

- **ブロッキング指摘が 1 件以上 → REJECT。0 件 → APPROVE**（非ブロッキング指摘が残っていてもよい）
- 無効化の根拠（反例・観測）または初出ラウンドの経緯を書けない指摘は、ブロッキングにしない
- 非ブロッキング指摘を破棄しない。根拠つきで記録する
- 2 回目以降のレビューで再走査証跡が無い場合、その結果は無効
```

**認知負荷軽減ルール:**

- APPROVE → サマリー + レビュー範囲 + 再走査証跡（2 回目以降）+ 非ブロッキング指摘（あれば）
- REJECT → 上記に加えてブロッキング指摘（30 行以内）
