# 企画入力の契約

旧 SKILL.md「前提スキル状態確認」「Phase 1-2」「Phase 1-2b」の**知識部分**の移設先。
判定と検査は tayk MCP tool が持つ。ここにあるのは「返ってきた入力をどう読むか」だけ。

## 入力モードごとに使える材料

| モード | 企画生成に使える入力 |
|---|---|
| analytics | 日次収集データ + 構造化分析 + ベンチマーク + config |
| benchmark fallback | ベンチマーク + config（自チャンネル分析の示唆は使わない） |
| minimal | ユーザー直接入力（テーマ / ジャンル / 雰囲気）+ config |

転写モードで minimal になった場合は転写元が存在しないため、企画を生成しない。

## 分析結果の読み方

分析の正本は構造化データ側で、人間向けの Markdown は説明と数値引用として読む。
見出し表記や採番に依存せず、固定キーを直接入力にする。

| 入力 | 使い道 |
|---|---|
| 戦略的改善提案 | CTR 改善・コンテンツ最適化の方向性 |
| 推奨される次期コレクション候補 | データから導出されたテーマ候補 |
| 戦略ディスカッション | 長期視点の示唆 |

## 学び（insights）の扱い

過去サイクルの検証済みの学びは、入力モードに依存しない**追加**入力であって前提ガードではない。
企画根拠として引用した場合は、引用した学びの識別子と要点を候補に明記する。
学びの status 更新（採用 / 見送り）は tool の担当であり、agent は引用の事実を報告するだけでよい。
