# TTP（転写）の知識

旧 SKILL.md の「競合パターン分析ルール」「ttp_mode: true 側の企画根拠」の移設先。
**いつ・何を・どう転写するか**の判断基準であって、手順ではない。

## 転写の対象

| 転写する | 転写しない |
|---|---|
| タイトルの構造（要素の並び・情報量） | タイトルの文字列そのもの |
| テーマの型（場所 × 時間帯 × ムードの組み方） | 競合固有の地名・キャラ名 |
| 利用シーンの訴求構造 | シリーズ名・ブランド表現 |
| 満たしている欲求とその訴求経路 | サムネの画像・レイアウトの直接模写 |

## 欲求整合の判定

転写元が満たしている欲求を特定し、企画の**タイトル・サムネイル・楽曲/音楽性の 3 つすべて**が
同じ欲求を満たすかを確認する。表面要素だけが一致して欲求が一致しない案は採用しない。

| 状態 | 判定 |
|---|---|
| 3 要素が同じ欲求を指している | OK |
| タイトルだけ一致し、音楽性が別の欲求を指している | REJECT |
| 欲求を特定できない（語彙のソースが無い） | `推定` と明記し、根拠を添える |

## 高再生の読み方

| 観測 | 読み |
|---|---|
| 高再生タイトルに共通する情景描写の具体性 | 具体性と CTR は相関する。具体的な場所 + ムードが情景想起を助ける |
| 低再生タイトルの抽象性 | 抽象的・汎用的なテーマは CTR が低い |
| 競合がカバー済みのテーマ | 転写モードでは**避けない**。実績のある優先候補として扱う |

## 差別化軸との関係

転写モードでは差別化軸（location / time_of_day / activity / mood）の掛け合わせを
候補生成に**使わない**。各候補は別々の当たり動画に対応させ、転写元を候補ごとに変えることで幅を出す。

差別化軸を使うのは非転写モードのときだけで、その場合も軸の値をサムネプロンプト本文に
書き出すと参照画像のスタイルアンカーが効かなくなる（構図ロック）。軸の値は
音楽プロンプト・概要欄・タイトルなど文字側でのみ字義通り使う。
