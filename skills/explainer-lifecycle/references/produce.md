# produce 区間: 台本・ショートの候補 → 図解 → 音声 → 描画 → プレビュー

入口は [SKILL.md](../SKILL.md)。失敗したら [failures.md](failures.md)。

前提: 企画ゲートが承認されていて、かつ動画がやめられていない（`video_status` の `gateRecords` の企画ゲートの最後の記録が承認で、`abandoned` が false）。この区間の tool は、承認の前は `ProduceGateNotApproved` で失敗する。

カットは名前で指す。長尺は `long`（各 tool の `cut` を省くと長尺）、ショートの候補ごとに `short-<番号>-clip`（切り抜き）と `short-<番号>-dedicated`（専用）の 2 つ。ショートの候補は 0 件でもよい。

## 1. 台本

`video_write_script` を呼ぶ。シーンの並び、シーンごとの段落の並び。本文に読み仮名 `{表記|読み}` を添えられる（字幕と画面は表記、音声合成は読み）。読み仮名の閉じ忘れ・入れ子・空は `InvalidReadingMarkup`、1 段落が長すぎると `ParagraphTooLong` で、何も書かれない。書き直すと台本が置き換わる。

## 2. ショートの候補

見どころごとに `video_write_short` を呼ぶ。

- `number`（1 から）、`range`（長尺の台本から切り抜く段落の範囲。両端を含み、シーンをまたいでよい）、`hook`（画面の上に出す文言。読み上げない）、`scenes`（専用ショートの台本）。
- 直すと新しい版が積まれ、最後の版が有効になる。同じ内容を書いても何も積まない。
- 減らすときは `video_withdraw_short`。取り下げても何も消えず、同じ番号を書き直すと戻る。
- ショートは 60 秒以内。長さは、composition を組むときと音声を混ぜるときに確かめる（`ShortTooLong`）。

## 3. 図解

シーンごとに `video_write_diagram` を呼ぶ。台本のシーン 1 つ分の絵で、動かす時刻は秒ではなく台本上の位置（段落 `P`、または `P.K` で P 段落目の K 番目の句）で書く。字幕は図解に描かない。台本のすべてのシーンに図解が要る。

- 違反はまとめて返る（`InvalidDiagrams`）。何も書かれないので、直して同じシーンを書き直す。
- 専用ショートの図解は `short` に候補の番号を付けて書く（専用の台本のシーンに対して）。切り抜きショートは長尺の図解を使うので、専用の図解は要らない。

## 4. 音声

1. `video_synthesize_narration` を呼ぶ。段落ごとに音声合成し、ナレーショントラックとタイミング表を作る。
   - すでに合成した段落（読み・声・演出指示が同じ）は再利用し、課金しない。表記だけを直したときは合成し直さない。
   - 途中で落ちても、合成済みの段落は残る。再実行すると足りない分だけを合成する。
   - 全段落を合成し直したいときだけ `force`。
   - 専用ショートの候補ごとに、`short` に番号を付けて呼ぶ（専用の台本から作る）。切り抜きは長尺のナレーションから切り出すので不要。
2. `video_mix_audio_track` を呼ぶ。ナレーションに BGM（チャンネルのプールの曲）を重ね、音量をそろえた最終の音声トラックを作る。
   - 曲は動画の ID から巡回で決まる。プールの曲を指定するときは `song`。
   - 鍵（ナレーション・タイミング表・曲・音量など）が同じなら再利用する。作り直すときは `force`。
   - カットごとに呼ぶ（`cut` に `short-<番号>-clip` または `short-<番号>-dedicated`）。

## 5. 描画

カットごとに、次の順で呼ぶ。

1. `video_assemble_composition`: 図解・字幕・テーマから composition（自己完結した HTML 1 枚）を組む。ブラウザは使わない。鍵が同じなら既存を返し、組み直すときは `force`。
2. `video_render_cut`: composition と最終の音声トラックから mp4 を書き出す。入力が変わっていなければ既存を返す（書き出しの事実は積まない）。作り直すときは `force`。
3. `video_preview_cut`: セグメントごとに最後のフレームの PNG を撮る。composition が同じなら既存を返す。撮り直すときは `force`。

カットを描き直すと最後の書き出しが新しくなり、そのカットの古いプレビューは公開ゲートの条件を満たさなくなる。描き直したら、プレビューも撮り直す（composition の鍵が変わっていれば `force` なしで撮り直される）。

## 6. 公開ゲートの前

1. 全カット（長尺と、取り下げていない各ショートの候補の切り抜き・専用）を描画し、プレビューを撮る。
2. `video_status` の `cuts` と `shorts` で、SKILL.md の「公開ゲートの前」の 3 つの条件を確かめる。満たしていないカットがあれば、足りない手順に戻る。
3. 満たしたら、プレビューの場所を人間に伝えて判断を求める。公開ゲートの判断と投稿は、この codec の範囲の外。
