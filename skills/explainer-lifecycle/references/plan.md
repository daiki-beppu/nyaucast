# plan 区間: 題材収集 → 企画 → サムネイル

入口は [SKILL.md](../SKILL.md)。企画ゲートの判断基準と作り直しの手順は SKILL.md にある。失敗したら [failures.md](failures.md)。

## 1. 題材を決める

1. `explainer_fetch_topic_candidates` を呼ぶ。読み取り専用で、何も書かない。
   - `genre` と `hitPatterns` はチャンネルの宣言。企画の当たる型は、ここにあるキーから選ぶ。
   - `candidates` は登録したフィードの記事。すでに企画の主な出典になっている記事（やめた動画のものも含む）は出てこない。
   - `failedFeeds` に読めなかったフィードが出る。1 つ失敗しても呼び出しは失敗しない。
2. 候補から題材を選ぶ。候補に良いものが無ければ、人間か agent が自分で題材を考えてよい（出典が無い企画になる）。選べないときは人間に相談する。
3. 1 つの題材から作る動画は 1 本。選んだ記事がすでに企画になっていれば、手順 2 に戻って別の題材を選ぶ。

## 2. 企画を書く

`explainer_write_plan` を呼ぶ。

- `title`（タイトル案）、`points`（要点）、`sources`（出典。主な出典を先頭に。URL・記事タイトル・取得時刻だけで、本文は書かない）、`hitPattern`（宣言済みの当たる型のキー）。
- `videoId` を省くと新しい動画ができ、返ってくる `videoId` がこの後すべての tool の入力になる。
- `created` が `false` なら、同じ題材の動画がすでにある。別の題材にするか、その動画を続ける。
- 企画を直すときは `videoId` を付けて書き直す（新しい版になる。同じ内容なら何も積まない）。企画ゲートの承認の後は書き換えられない。
- 書き直すと、すでに選んだサムネイルの選択が古くなる。サムネイルを選び直してもらう必要がある。

## 3. サムネイルを作る

1. `video_generate_thumbnails` を呼ぶ。`text`（サムネイルの文言。動画のタイトルとは別に書く）と `background`（背景の描写）を渡す。
   - チャンネルのサムネイルの型（画風・参照画像・禁止語・枚数・provider）に従って、候補を何枚か作る。
   - `force` なしで再実行すると、最後の回で足りない番号だけを作る。検査に落ちた番号は作った扱いで、作り直さない（課金された 1 回の事実）。全部そろった回では外部呼び出しをしない。
   - `force` を付けると、全候補の新しい回を作る。理由なしに付けない。
2. 候補を `video_status` の `thumbnails` で確かめる。文字が読めない・誤字があるなどの候補は `video_exclude_thumbnail` で理由つきで落とす（消えはしないが、選べなくなる）。
3. 良い候補が無ければ、`text` か `background` を直して `force` つきで新しい回を作る。
4. 候補が残ったら、人間に候補を示して選んでもらう。選ぶのは人間で、`nyaucast video thumbnail <id> <回>-<番号>` を叩く（例: 2 回目の 1 番は `2-1`）。人間が自分の画像を使うなら `nyaucast video thumbnail <id> --file <パス>`。agent は叩かない。

## 4. 企画ゲートの前

1. `video_status` で `awaitingApproval` が `produce` になっていることを確かめる。ならないときは、先に `abandoned` と `gateRecords` を見て、SKILL.md の「企画ゲート」の分岐に従う（企画ゲートが承認済みで `abandoned` が false なら produce 区間、やめた動画は NO-GO になったゲートで分かれる）。どれでもなければ、企画があるか、サムネイルの選択が企画の最後の更新より新しいかを確かめる。
2. SKILL.md の「企画ゲート」に従って、人間に判断を求める。
3. 承認（`nyaucast video produce <id>`）が `gateRecords` に出たら、[produce.md](produce.md) に進む。
